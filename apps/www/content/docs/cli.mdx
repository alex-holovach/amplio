```bash
npx @useamplio/cli@alpha <command>
```

## init

```bash
npx @useamplio/cli@alpha init --service my-app --yes
npx @useamplio/cli@alpha init --service my-app --middleware hono --event auth.user.signed_up --yes
npx @useamplio/cli@alpha init --paths   # adds ~telemetry/* tsconfig alias
npx @useamplio/cli@alpha init --skip-install
```

Creates `telemetry/`, `amplio.json`, `components.json`, installs `@useamplio/amplio` + `zod`. Detects Next.js / Hono / Express / Fastify from `package.json` and scaffolds middleware plus a starter event when possible.

Under `--yes` (or `--wire`) in a create-t3-app layout, `init` also auto-wires the app: `route.ts` → `withAmplio`, `trpc.ts` → `amplioTrpcMiddleware`, and the NextAuth route when present. The `~telemetry/*` tsconfig alias is applied by default when a tsconfig exists (`--no-paths` opts out).

Other flags: `--package-manager <pnpm|npm|yarn|bun>`, `--no-typescript`, `--cwd <path>`, `--verbose` (stream the raw install log). Re-running `init` is idempotent — existing files are left unchanged.

## paths

```bash
npx @useamplio/cli@alpha paths
```

Writes the `~telemetry/*` tsconfig path alias (JSONC-comment-safe) and nothing else.

## add

```bash
npx @useamplio/cli@alpha add event post.created
npx @useamplio/cli@alpha add middleware hono
npx @useamplio/cli@alpha add sink json
npx @useamplio/cli@alpha add enricher query-allowlist
npx @useamplio/cli@alpha add integration next-auth
npx @useamplio/cli@alpha add sink otlp --dry-run
```

Valid kinds: `event`, `middleware`, `sink`, `enricher`, `integration`.

- Event names need two+ lowercase dot-separated segments (`post.created`, `auth.user.signed_up`). `add event` prints whether it `matched registry event` or `generated starter schema`.
- `add` never overwrites an existing file under `telemetry/` — re-run with `--force` to overwrite with the current registry template.
- `--dry-run` previews files, wiring, and dependencies without writing anything.
- `add integration <id>` (next-auth, better-auth, clerk, resend, polar) prints the manual wiring steps after installing.

`amplio add` wires barrels, `logger.ts`, `.gitignore`, and `.env.example` in one command. shadcn drops files only — run `doctor --fix` after.

## doctor

```bash
npx @useamplio/cli@alpha doctor
npx @useamplio/cli@alpha doctor --fix
npx @useamplio/cli@alpha doctor --strict   # CI gate
```

Checks middleware exports, event barrels (in both directions — missing exports *and* stale ones), Turbopack `../logger` imports, the `NEXT_RUNTIME` instrumentation guard, and T3 wiring (`route.ts` still wraps with `withAmplio`, `trpc.ts` still uses `amplioTrpcMiddleware`).

`--fix` regenerates missing event barrel exports and prunes stale ones. `--strict` exits non-zero on warnings for CI; without it, doctor prints an explicit `(exit 0 with warnings …)` note.

## smoke

```bash
npx @useamplio/cli@alpha smoke http://localhost:3000/api/health
```

End-to-end verification: requests the URL, watches `amplio*.jsonl` for a newly emitted row, and reports PASS/FAIL with a diagnosis (wrong port / unwired route / init never ran). Requires the JSON sink (`amplio add sink json`); `--timeout <seconds>` adjusts the wait (default 10).

## shadcn registry

Hosted at `/r/{name}.json` on this site. `init` writes:

```json
{
  "registries": {
    "@useamplio": "https://amplio-ruddy.vercel.app/r/{name}.json"
  }
}
```

```bash
npx shadcn@latest add @useamplio/sink-json
npx shadcn@latest add @useamplio/middleware-hono
```

Files land under `telemetry/` at the repo root (targets are root-anchored, even with a `src/` layout). Browse hosted items at [/r/registry.json](/r/registry.json).

**"Item not found":** only registry items are hosted. Events generated by `amplio add event your.name` are starter schemas created directly in your repo — `npx shadcn add @useamplio/event-your-name` 404s by design.
