---
title: Sinks & enrichers
description: Deliver, enrich, redact, sample, and flush completed Events.
---

After a root Event closes, Amplio validates and sanitizes its detached record, adds resource
attributes, applies redaction, makes a sampling decision, and invokes configured sinks. Delivery
failures never replace application results or thrown values.

## Configure runtime once

```ts
// telemetry/runtime.ts
import { init } from "@useamplio/amplio";
import { consoleSink } from "./sinks/console.js";

init({
  service: "orders-api",
  env: process.env.NODE_ENV ?? "development",
  sinks: [consoleSink],
});
```

`init()` returns `void` and exports no logger. Load this file once from server startup or framework
instrumentation.

## Add a sink

```bash
npx @useamplio/cli@alpha add sink console
npx @useamplio/cli@alpha add sink json
npx @useamplio/cli@alpha add sink otlp
```

- `console` writes one JSON object per kept root Event.
- `json` appends JSON lines for local inspection and `amplio smoke`.
- `otlp` exports log records to an OpenTelemetry collector.

Sink source is copied under `telemetry/sinks/` and remains editable.

The OTLP sink promotes the current HTTP fields (`http.method`, `http.route`, and `http.status`) and
the bounded repeated `rpc.procedures` branch by default. Procedure arrays use OTLP `arrayValue`
entries containing key-value lists. Operational values under `record.resource` become typed OTLP
resource attributes, and batched records with different resource values stay in separate
`resourceLogs` groups.

Default export-failure warnings expose only `network_error` or the collector's HTTP status, never a
caught error message. `throwOnError: true` is the explicit opt-in that rethrows the original network
error to application code.

## Sink contract

```ts
import type { Sink } from "@useamplio/amplio";

export const customSink: Sink = (record) => {
  queue.push(record);
};

customSink.flush = async () => {
  await queue.drain();
};
```

A sink synchronously accepts or enqueues the record before returning. An optional returned thenable
tracks completion of already accepted work. Throws and rejections are isolated; later sinks still
run.

Each sink receives its own immutable value. Mutation attempts cannot affect another sink or later
Events.

## Backpressure

```ts
init({
  service: "orders-api",
  env: "production",
  sinks: [otlpSink, consoleSink],
  delivery: {
    maxPendingPerSink: 1_024,
    flushTimeoutMs: 5_000,
  },
});
```

When one sink reaches its pending bound, Amplio skips only that sink for the new Event, reports
`sink_backpressure_drop`, and continues healthy sinks. Sink adapters must also bound their own
internal queues.

## Flush

```ts
import { flush } from "@useamplio/amplio";

const result = await flush({ timeoutMs: 5_000 });

if (result.pending > 0 || result.failures > 0) {
  console.error("Amplio delivery did not fully drain", result);
}
```

Flush invokes every retained sink hook synchronously, then waits for accepted delivery at its
start-time watermark. New delivery belongs to a later call. The finite result is
`{ completed, pending, failures }`; flush does not reject because a sink failed.

Call it after the application work you intend to drain has finished. Open root Events that have not
reached delivery are outside the watermark.

## Resource enrichers

Enrichers receive resource attributes only:

```ts
init({
  service: "orders-api",
  env: "production",
  sinks: [otlpSink],
  enrichers: [
    (resource) => ({
      ...resource,
      region: process.env.AWS_REGION ?? "unknown",
      release: process.env.RELEASE_SHA ?? "unknown",
    }),
  ],
});
```

They cannot read or rewrite semantic Event fields. Failures are diagnosed and later enrichers still
run.

## Redaction

Use a whole-record redactor for policy that depends on semantic placement:

```ts
init({
  service: "orders-api",
  env: "production",
  sinks: [otlpSink],
  redactor(record) {
    return removePrivateFields(record);
  },
});
```

Redaction runs before sampling and sinks. If the redactor throws or returns an invalid record, the
Event is dropped fail-closed. Application behavior is unchanged.

The declarative `redact` option remains useful for path and pattern rules:

```ts
init({
  service: "orders-api",
  env: "production",
  sinks: [otlpSink],
  redact: {
    fields: ["authorization", "cookie", "token"],
    patterns: [/Bearer\s+\S+/gi],
  },
});
```

Default framework Plugins omit query strings, bodies, headers, and raw URLs. Project only stable,
allowlisted values into Event fields.

## Sampling

```ts
init({
  service: "orders-api",
  env: "production",
  sinks: [otlpSink],
  sampling: {
    rate: 0.1,
    keep: [
      { field: "success", equals: false },
      { field: "@event", equals: "billing.reconciliation" },
      { field: "http.status", gte: 500 },
    ],
  },
});
```

Sampling sees the complete redacted root record. Nested Events are never sampled independently. A
custom `sampler(record)` may replace the declarative decision when policy needs code.

## Runtime replacement

Each open root keeps the configuration generation it started with. A later `init()` affects new
roots only. Retired generations remain flushable while they own open roots or accepted delivery,
within finite count and TTL bounds. Replacement is atomic and never appends duplicate sinks.
