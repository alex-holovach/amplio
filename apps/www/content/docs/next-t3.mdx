The create-t3-app shape keeps telemetry source at the repository root. Route and procedure code
stays ordinary; Next and tRPC Plugins attach at their native seams.

## Scaffold

```bash
npx @useamplio/cli@alpha init --service t3-app --paths
npx @useamplio/cli@alpha add plugin next --source-only
npx @useamplio/cli@alpha add plugin trpc --event http.request
```

Next route selection is application-specific, so `--source-only` copies editable source without
pretending it is active. Attach `withAmplio()` to the intended route export below, then promote that
verified manual boundary with `add plugin next --target <route-file>`. The tRPC command can wire one
unambiguous `initTRPC` construction and its direct procedure bases atomically.

Target tree:

```text
telemetry/
  events/
    http-request.ts
  plugins/
    next.ts
    trpc.ts
  sinks/
    console.ts
  runtime.ts
instrumentation.ts
```

Load runtime once from Next instrumentation:

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME === "nodejs") {
    await import("./telemetry/runtime");
  }
}
```

## Mount tRPC in the HTTP Event

```ts
// telemetry/events/http-request.ts
import { event } from "@useamplio/amplio";
import { z } from "zod";
import { TrpcPlugin } from "../plugins/trpc";

export const HttpRequest = event({
  id: "http.request",
  version: 1,
  schema: z.object({
    request_id: z.string(),
    http: z.object({
      method: z.string(),
      route: z.string().optional(),
      status: z.number().int().optional(),
    }),
  }),
  tree: {
    rpc: TrpcPlugin.events,
  },
});
```

`TrpcPlugin.events.procedures` is a bounded repeated duration Event for queries and mutations. Every
recorded occurrence owns its stable path, type, duration, success, and structured failure state.
Subscriptions pass through unchanged because this middleware seam cannot observe stream completion.

## Own the App Router boundary

Wrap the catch-all route with an explicit stable route template:

```ts
// src/app/api/trpc/[trpc]/route.ts
import type { NextRequest } from "next/server";
import { withAmplio } from "~telemetry/plugins/next";

const handler = (request: NextRequest) =>
  fetchRequestHandler({
    endpoint: "/api/trpc",
    req: request,
    router: appRouter,
    createContext: createTRPCContext,
  });

export const GET = withAmplio("/api/trpc/[trpc]", handler);
export const POST = withAmplio("/api/trpc/[trpc]", handler);
```

The Next Plugin records method, explicit route, returned status, and duration. A thrown handler keeps
method and route but does not invent a final HTTP status that Next never exposed. The route argument
is required; the Plugin intentionally has no `withAmplio(handler)` overload.

Record this exact customer-owned route as the active boundary:

```bash
npx @useamplio/cli@alpha add plugin next \
  --target 'src/app/api/trpc/[trpc]/route.ts'
```

The CLI authenticates the local Plugin import, stable route literal, handler argument, and exported
HTTP method. It stores the selected composition root but does not rewrite the route. If verification
fails, source-only state and every project byte are preserved.

## Attach tRPC once

```ts
// src/server/api/trpc.ts
import { TrpcPlugin } from "~telemetry/plugins/trpc";

export const publicProcedure = t.procedure.use(TrpcPlugin());
export const protectedProcedure = t.procedure.use(TrpcPlugin());
```

tRPC v11 represents downstream failures as a resolved `{ ok: false, error }` value. The Plugin marks
the nested Event failed and returns that same resolved value; thrown values are rethrown unchanged.
Subscriptions are returned by Promise identity and omitted rather than reported with a false duration.

For a batched HTTP request, procedure Events remain in invocation order beneath the single root
record.

## Add provider Plugins

```bash
pnpm add resend
npx @useamplio/cli@alpha add plugin resend --event http.request
```

The CLI mounts `ResendPlugin.events` in the same root and wraps the existing Resend construction
once. Route and procedure code continues calling the normal provider client.

## Server callers

A direct server caller that does not run inside the HTTP root cannot contribute to that HTTP Event.
If it represents an independent unit of work, give it its own root Event and boundary Plugin. Do not
pretend it belongs to an unrelated browser request.

## RSC rendering

Rendering can use an independent root Event:

```ts
const PageRender = event({
  id: "page.render",
  version: 1,
  schema: z.object({ page: z.object({ name: z.string() }) }),
});

export function withAmplioRender(page, render) {
  return PageRender.handle(render, {
    input: () => ({ page: { name: page } }),
  });
}
```

This does not claim procedure calls executed outside its actual async context.

## Validate

```bash
npx @useamplio/cli@alpha doctor
pnpm exec tsc --noEmit
pnpm build
```

`doctor --strict` verifies the adopted Next route through the same native-shape predicate used by
installation. Removal never rewrites this customer-owned file and refuses to delete the Plugin while
the route still imports or references it. Detach the wrapper and import, then retry removal. A real
route request and captured Event remains the final proof that the application executes the boundary.

Next uses bundler-mode extensionless imports throughout the generated telemetry graph. Generic
NodeNext projects use explicit `.js` specifiers.
