## Lifecycle

```typescript
import { logger } from "./telemetry/logger";
import { AuthUserSignedUp } from "./telemetry/events/auth/user-signed-up";

const log = logger.event(AuthUserSignedUp);

log.set({ user: { id: "u_1" } });
log.set({ signup: { method: "oauth" } }); // deep-merge
log.emit(); // validate, redact, drain sinks, seal
```

`.set()` deep-merges nested objects and mutates the logger in place (it returns the same instance, so `getLogger()` stays valid in middleware ALS). `null` overwrites; `undefined` in a patch is skipped; arrays are **replaced**, not concatenated.

## Errors

```typescript
try {
  await work();
} catch (err) {
  log.error(err, { status: 500 });
}
log.emit();
```

`.error()` records structured failure (`success: false`) but does not emit — call `.emit()` after.

For `Error` instances it records `error.message`, `error.name` (the thrown class name), and `error.code` only when the thrown value carries a real string/number `code`. Structured errors from `createError({ message, why, fix, code })` are recorded field-for-field.

## Return value

`.emit()` returns the finalized record, or **`null`** when:

- `init()` never ran (dev warns)
- the logger was already sealed (repeat `.emit()`)
- sampling skipped sink delivery (enrichers + redaction still run)

## child() for correlated rows

```typescript
const ev = getLogger().child(PostCreated); // clock starts here
const post = await db.insert(...);
ev.set({ post: { id: post.id } }).emit();
```

`duration_ms` on a child measures time since `.child()` — create the child **before** work to time the operation. Or use `.time()`:

```typescript
await getLogger().time(PostCreated, async (ev) => {
  const post = await createPost();
  ev.set({ post: { id: post.id } });
  return post;
});
```

## create() for jobs and scripts

Outside request scope (cron jobs, scripts, CLI runs), `logger.create()` starts a standalone wide-event scope:

```typescript
logger.create({ job: "nightly-sync" })
  .set({ records_processed: 42 })
  .emit();
```

## success field

When neither `status` nor an explicit `success` is set, `success` is **omitted** from the record. Numeric `status` in `[200, 400)` or the exact string `"ok"` derives `success: true`. Explicit `success` always wins.

For domain events without `status`, filter with `success != false` rather than `success = true`.

## flush()

```typescript
import { flush } from "@useamplio/amplio";

await handler();
await flush(); // await pending async sink deliveries
```

Use with serverless `waitUntil` / Next.js `after` when async sinks (OTLP batch) must complete.

## Validation

Schema validation runs at emit time and **soft-fails** outside `NODE_ENV=test`: a payload that violates its schema still emits, tagged with `validation.issues` and `success: false`. Pass `init({ strict: true })` to throw instead.

## Testing events

Under `NODE_ENV=test`, validation hard-throws `AmplioValidationError` (with `issues` naming the bad paths), and `init()` is re-runnable via `resetConfigForTests()`. Use `memorySink()` and assert on delivered records:

```typescript
import { beforeEach, expect, it } from "vitest";
import { init, memorySink, resetConfigForTests } from "@useamplio/amplio";

const sink = memorySink();

beforeEach(() => {
  resetConfigForTests();
  init({ service: "test", env: "test", sinks: [sink] });
  sink.clear();
});

it("emits post.created", async () => {
  await createPost({ text: "hi" });
  const row = sink.records.find((r) => r["@event"] === "post.created");
  expect(row).toMatchObject({ post: { text: "hi" } });
});
```
