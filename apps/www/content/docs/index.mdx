**amplio** is shadcn for observability: typed event schemas, a tiny runtime, and generated `telemetry/` code you read and edit like application code.

## Quick start

```bash
npx @useamplio/cli@alpha init --service my-app --yes
npx @useamplio/cli@alpha add event auth.user.signed_up
npx @useamplio/cli@alpha add middleware hono
```

`init` detects Next.js, Hono, Express, or Fastify from `package.json` and can scaffold middleware plus a starter event in one shot.

> The unscoped npm name `amplio` is blocked by typo-squatting rules. Always use `@useamplio/cli@alpha`.

## Emit a wide event

```typescript
import { logger } from "./telemetry/logger";
import { AuthUserSignedUp } from "./telemetry/events/auth/user-signed-up";

logger
  .event(AuthUserSignedUp)
  .set({
    user: { id: "u_123" },
    signup: { method: "email" },
  })
  .emit();
```

Example record (fields vary by schema and enrichers):

```json
{
  "service": "my-app",
  "env": "development",
  "timestamp": "2026-08-07T16:30:00.000Z",
  "duration_ms": 12,
  "event": "auth.user.signed_up",
  "@event": "auth.user.signed_up",
  "user": { "id": "u_123" },
  "signup": { "method": "email" }
}
```

`@event` is the reserved canonical event name; `event` duplicates it for sinks and queries that avoid `@`-prefixed keys (pass `init({ canonicalKeyOnly: true })` to emit only `@event`). `success` appears only when `status` or an explicit `success` is set — clean domain rows omit it, so filter with `success != false`, not `success = true`.

## Correlated domain events

Inside request middleware scope, `.child()` emits a separate row that shares the request's `request_id`:

```typescript
import { getLogger } from "@useamplio/amplio";
import { AuthUserSignedUp } from "./telemetry/events/auth/user-signed-up";

// inside withAmplio / hono middleware:
getLogger()
  .child(AuthUserSignedUp)
  .set({ user: { id: "u_123" }, signup: { method: "email" } })
  .emit();
// two rows: http.request spine (middleware) + auth.user.signed_up (same request_id)
```

## Packages

| Package | Role |
|---|---|
| `@useamplio/cli` | Scaffolding (`init`, `add`, `doctor`) |
| `@useamplio/amplio` | Runtime (`defineEvent`, `init`, `.set()`, `.emit()`) |

The CLI is a scaffolder — once `telemetry/` exists, you can remove it and keep editing events, middleware, and sinks with only `@useamplio/amplio` installed.
