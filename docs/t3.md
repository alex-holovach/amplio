# create-t3-app guide

Amplio gives a Next.js + tRPC application one typed HTTP Event assembled by open-code Plugins.
Route handlers, procedures, and domain functions keep their normal interfaces. The Next Plugin owns
the request boundary, and the tRPC Plugin contributes procedure Events through tRPC's native
middleware seam.

The public mental model has only two semantic concepts:

- an **Event** is a versioned schema and a declared tree;
- a **Plugin** connects exact Event definitions to a native framework, provider, or local seam.

Boundary and contributor describe Plugin roles. They are not additional APIs.

## 1. Initialize the repository

Run these commands from the create-t3-app root:

```bash
pnpm add @useamplio/amplio zod
pnpm add --save-dev @useamplio/cli
pnpm exec amplio init --service my-t3-app --paths
pnpm exec amplio add plugin next --source-only
pnpm exec amplio add plugin trpc --event http.request
```

The Next route wrapper is installed with `--source-only` because the CLI cannot safely choose which
route owns the application boundary. You attach it explicitly in section 4, then promote that exact
file with `add plugin next --target <route-file>`. The tRPC install can be active when the project
has one unambiguous `initTRPC` construction and its direct procedure bases are in the same file.
Otherwise it aborts without partial writes.

The resulting source is small:

```text
telemetry/
├── events/
│   └── http-request.ts
├── plugins/
│   ├── next.ts
│   └── trpc.ts
├── sinks/
│   └── console.ts
└── runtime.ts

amplio.json
src/instrumentation.ts
```

The generated tree contains only Events, Plugins, sinks, and runtime configuration. `amplio.json`
stores install metadata for the CLI and is never read at runtime.

## 2. Load the runtime once

`telemetry/runtime.ts` calls `init()` and exports no logger:

```ts
import { init } from "@useamplio/amplio";
import { consoleSink } from "./sinks/console";

init({
  service: "my-t3-app",
  env: process.env.NODE_ENV ?? "development",
  sinks: [consoleSink],
});
```

Load it from Next's server instrumentation hook:

```ts
// src/instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME === "nodejs") {
    await import("../telemetry/runtime");
  }
}
```

Do not import the runtime or Plugins from a `"use client"` module. Amplio's semantic runtime is
server-only and uses async context.

## 3. Read the declared Event tree

Installing the tRPC Plugin mounts its exact Event definitions under a key you can see and edit:

```ts
// telemetry/events/http-request.ts
import { event } from "@useamplio/amplio";
import { z } from "zod";
import { TrpcPlugin } from "../plugins/trpc";

export const HttpRequest = event({
  id: "http.request",
  version: 1,
  schema: z.object({
    request_id: z.string(),
    http: z.object({
      method: z.string(),
      route: z.string().optional(),
      status: z.number().int().optional(),
    }),
  }),
  tree: {
    rpc: TrpcPlugin.events,
  },
});
```

The `rpc` key chooses placement in the final record. `TrpcPlugin.events.procedures` is a bounded,
repeated duration Event for queries and mutations. Every recorded occurrence owns its stable path,
type, duration, success, and structured failure state. Subscriptions are returned unchanged and
omitted because this middleware seam cannot observe stream completion. A request that does not
execute a recorded procedure simply omits the branch.

The tree is ordinary TypeScript. There is no `optional()`, `many()`, `group()`, or mutable Event
builder in application code.

## 4. Attach the Next boundary

Wrap the catch-all tRPC route and supply a stable route template:

```ts
// src/app/api/trpc/[trpc]/route.ts
import type { NextRequest } from "next/server";
import { withAmplio } from "~telemetry/plugins/next";

const handler = (request: NextRequest) =>
  fetchRequestHandler({
    endpoint: "/api/trpc",
    req: request,
    router: appRouter,
    createContext: createTRPCContext,
  });

export const GET = withAmplio("/api/trpc/[trpc]", handler);
export const POST = withAmplio("/api/trpc/[trpc]", handler);
```

Verify and record this customer-owned boundary without rewriting the route:

```bash
pnpm exec amplio add plugin next \
  --target 'src/app/api/trpc/[trpc]/route.ts'
```

The target is an existing source file relative to the project. Absolute paths, `..`, missing or
non-source files, and symlinks escaping the project fail before writes. It narrows discovery to one
file but does not weaken import/provider authentication or select between multiple supported seams
inside that file.

`withAmplio()` opens `HttpRequest`, returns the handler's original `Response`, and closes the Event
when that response or thrown value settles. The wrapper records the request method, the explicit
route template, final status when Next exposes one, duration, and outcome. The route argument is
required; there is no handler-only overload.

Never use `request.nextUrl.pathname` as the semantic route. It may contain customer identifiers,
and a raw URL or query string is not a stable route name.

## 5. Attach the tRPC contributor

The active tRPC install adds one Plugin-produced middleware to each direct base procedure:

```ts
// src/server/api/trpc.ts
import { TrpcPlugin } from "~telemetry/plugins/trpc";

const t = initTRPC.context<typeof createTRPCContext>().create();
const amplioMiddleware = t.middleware(TrpcPlugin());

export const publicProcedure = t.procedure.use(amplioMiddleware);
export const protectedProcedure = t.procedure
  .use(amplioMiddleware)
  .use(enforceUserIsAuthed);
```

`TrpcPlugin()` returns a normal tRPC middleware function. It observes `options.next()` and returns
the same resolved value or rethrows the same error. tRPC v11 can represent downstream failure as a
resolved `{ ok: false, error }`; the Plugin recognizes that native shape without changing it.
Subscriptions pass through by Promise identity and are not recorded as false-duration Events.

Putting the Amplio middleware first means rejected authentication is still represented as a failed
procedure Event. Batched calls retain invocation order beneath the single HTTP root.

There is no logger, `.set()`, `.emit()`, capture call, or active-Event accessor in a procedure:

```ts
export const createPost = protectedProcedure
  .input(CreatePostInput)
  .mutation(({ ctx, input }) => ctx.db.post.create({ data: input }));
```

## 6. Add provider semantics

Provider Plugins use the same tree and attach once at provider construction or configuration.

For Resend:

```bash
pnpm add resend
pnpm exec amplio add plugin resend --event http.request
```

```ts
import { Resend } from "resend";
import { ResendPlugin } from "~telemetry/plugins/resend";

export const resend = ResendPlugin(new Resend(process.env.RESEND_API_KEY));
```

The CLI mounts `ResendPlugin.events` under `tree.email` and wraps one unambiguous `new Resend(...)`
construction. Existing calls remain native:

```ts
await resend.emails.send(message);
```

For Better Auth:

```bash
pnpm add better-auth
pnpm exec amplio add plugin better-auth --event http.request
```

```ts
import { BetterAuthPlugin } from "~telemetry/plugins/better-auth";

export const auth = betterAuth({
  database,
  plugins: [BetterAuthPlugin()],
});
```

The Better Auth Plugin uses official `after` hooks. It contributes confirmed sign-in and sign-up
semantics under `tree.auth`; it does not capture email, session IDs, tokens, cookies, bodies,
headers, or raw callback URLs.

If a provider construction or configuration seam is absent or ambiguous, active installation
fails without writing a half-connected Plugin. Use `--source-only` only when you intend to inspect
and attach the open code yourself.

## 7. Keep business code clean

Application and domain code keeps calling ordinary dependencies:

```ts
export async function createPost(input: CreatePostInput) {
  const post = await db.post.create({ data: input });

  await resend.emails.send({
    from: "posts@example.com",
    to: input.authorEmail,
    subject: "Post created",
    tags: [{ name: "template", value: "post-created" }],
  });

  return post;
}
```

Only composition roots import local Plugins: Next route exports, tRPC construction, provider
construction, Better Auth configuration, worker registration, and runtime bootstrap. Domain
modules import neither Amplio core nor local telemetry.

Removing an Amplio wrapper must change observability only. Return values, thrown values, native
Promise identity, framework ordering, callbacks, and provider inputs remain unchanged.

## 8. Understand the output

One successful batched request can produce one root record:

```json
{
  "@event": "http.request",
  "@event_version": 1,
  "service": "my-t3-app",
  "env": "development",
  "timestamp": "2026-08-14T07:00:00.000Z",
  "request_id": "req_01K2...",
  "duration_ms": 28,
  "success": true,
  "http": {
    "method": "POST",
    "route": "/api/trpc/[trpc]",
    "status": 200
  },
  "rpc": {
    "procedures": [
      {
        "path": "post.create",
        "type": "mutation",
        "duration_ms": 18,
        "success": true
      }
    ]
  },
  "email": {
    "sends": [
      {
        "provider": "resend",
        "template": "post-created",
        "duration_ms": 9,
        "success": true
      }
    ]
  }
}
```

The record is the declared Event tree, not a transport row joined to detached semantic rows by
request ID. The runtime validates, sanitizes, redacts, samples, and detaches the record before
delivery.

## 9. Verify the real seams

Run static checks first:

```bash
pnpm exec amplio doctor
pnpm exec tsc --noEmit
pnpm build
```

`doctor --strict` verifies the adopted Next route through the same native-shape predicate used by
installation. Removal never rewrites the customer-owned route and refuses to delete Plugin source
while a live Plugin import or reference remains. Detach the wrapper and import, then retry removal.
Prove runtime activation with the real request below; copied source alone is not evidence of a
working boundary.

Then exercise a real tRPC request with the JSON sink:

```bash
pnpm exec amplio add sink json
pnpm exec amplio smoke \
  'http://localhost:3000/api/trpc/post.hello?batch=1&input=%7B%7D'
```

Verify more than file presence:

- the HTTP response and error behavior are unchanged;
- exactly one `http.request` root record is delivered;
- `rpc.procedures` contains the expected stable procedure path and type;
- failures set structured Event failure fields without leaking error messages;
- raw URL, query, headers, cookies, bodies, tokens, and provider payloads are absent;
- a batched request preserves procedure invocation order;
- a direct server caller outside the HTTP boundary does not leak into an unrelated request.

Unit tests call domain functions directly without initializing Amplio. Test Event projections and
tree behavior separately with `@useamplio/amplio/testing` and a real boundary invocation.

## 10. Upgrade safely

After a Next, tRPC, auth-provider, or CLI upgrade:

```bash
pnpm exec amplio doctor
pnpm exec tsc --noEmit
pnpm build
```

Plugin source is application-owned open code. `amplio diff plugin <slug>` compares it with the
content-addressed installed base and current registry recipe. `amplio update plugin <slug>` performs
a three-way merge for non-overlapping source edits and fails closed for semantic, privacy, native
wiring, or merge conflicts. After a successful update, rerun type, framework, privacy, and
behavior-preservation tests before accepting the change.
