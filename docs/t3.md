# amplio + create-t3-app (Next 15, tRPC v11, App Router)

Concise wiring for a standard [create-t3-app](https://create.t3.gg) layout: `src/` app code, `telemetry/` at repo root, tRPC v11 App Router handler.

See also [ALPHA.md](../ALPHA.md) for the full alpha guide.

## 1. Scaffold

From your T3 project root:

```bash
npx @useamplio/cli@alpha init --service t3-app --yes
```

Under `--yes` (or with `--wire`), `init` also **auto-wires the T3 layout**: it wraps the handler export in `src/app/api/trpc/[trpc]/route.ts` with `withAmplio` and prepends `amplioTrpcMiddleware` to `publicProcedure` / `protectedProcedure` in `src/server/api/trpc.ts`. If your files have drifted from the stock T3 shape, `init` leaves them alone and prints the manual snippets below (sections 2–3).

`init` detects Next.js + `@trpc/server` and typically creates:

```
telemetry/
├── events/ …                 # starter event only when auth dep detected (or --event)
├── middleware/next.ts
├── middleware/trpc.ts      # side-effect import "../logger" at top (alpha.8+)
├── sinks/ …
└── logger.ts
amplio.json
components.json
src/instrumentation.ts    # imports telemetry/logger so init() runs at boot
```

`instrumentation.ts` is required — without it, `.emit()` before `init()` drops silently (dev warns per drop).

Optional path alias for shorter imports:

```bash
npx @useamplio/cli@alpha init --paths
# adds "~telemetry/*": ["./telemetry/*"] to tsconfig.json (JSONC-safe)
```

## 2. Wire the tRPC HTTP handler (manual — skip if init auto-wired)

File: `src/app/api/trpc/[trpc]/route.ts`

```ts
import { fetchRequestHandler } from "@trpc/server/adapters/fetch";
import { withAmplio } from "../../../../../telemetry/middleware/next";
import { appRouter } from "@/server/api/root";
import { createTRPCContext } from "@/server/api/trpc";

const handler = (request: Request) =>
  fetchRequestHandler({
    endpoint: "/api/trpc",
    req: request,
    router: appRouter,
    createContext: () => createTRPCContext({ headers: request.headers }),
  });

export const GET = withAmplio(handler);
export const POST = withAmplio(handler);
```

With `init --paths`, you can import `withAmplio` from `"~telemetry/middleware/next"`.

## 3. Wire tRPC middleware (manual — skip if init auto-wired)

File: `src/server/api/trpc.ts`

```ts
import { amplioTrpcMiddleware } from "../../../telemetry/middleware/trpc";

const amplioMiddleware = t.middleware(amplioTrpcMiddleware());
export const publicProcedure = t.procedure.use(amplioMiddleware);
// repeat for protectedProcedure / other bases as needed
```

`withAmplio` owns the `http.request` spine; `amplioTrpcMiddleware` annotates it with `trpc.path`, `trpc.type`, and status.

## 4. Domain events from procedures

Use `.child()` — not `.event()` on the request logger (that rebinds and seals the spine):

```ts
import { getLogger } from "@useamplio/amplio";
import { AuthUserSignedUp } from "../../../telemetry/events/auth/user-signed-up";

export const authRouter = createTRPCRouter({
  register: publicProcedure.mutation(async ({ ctx }) => {
    // … create user …
    getLogger()
      .child(AuthUserSignedUp)
      .set({ user: { id: "u_123" }, signup: { method: "email" } })
      .emit();
    // two rows: http.request spine + auth.user.signed_up (same request_id)
  }),
});
```

## 5. RSC server-caller path

Homepage / layout code that calls `createCaller()` (no HTTP request) does **not** go through `withAmplio`. `amplioTrpcMiddleware` creates its own spine:

- `event` / `@event`: `trpc.request`
- `transport`: `"server-caller"`
- `trpc.path`, `trpc.type` set from the procedure
- **No** `http.method: "TRPC"` or other fabricated `http.*` fields

Real browser/API tRPC calls through `/api/trpc` still produce `http.request` spines (unchanged).

## 6. Turbopack (`next dev --turbo`)

Turbopack can compile `instrumentation.ts` and route handlers into separate module graphs. Before alpha.8 that meant `init()` in instrumentation was invisible to middleware and events dropped silently.

Fixes: runtime stores `init()` / ALS on `globalThis[Symbol.for('amplio.state.v1')]`; middleware templates import `"../logger"` as a side effect; `amplio doctor` warns on stale middleware missing that import. Run `npx @useamplio/cli@alpha doctor` after upgrading.

## 7. Verify

```bash
pnpm dev
# ⚠ confirm the port Next actually bound — it silently moves to 3001+ if 3000 is
# busy, and a wrong-port curl looks identical to dropped events.
curl -s 'http://localhost:3000/api/trpc/post.hello?batch=1&input=…'   # adjust to your router
# expect JSON lines on stdout (console sink)
npx @useamplio/cli@alpha doctor
```

You should see at least one `http.request` row per HTTP tRPC call and separate domain rows for each `.child(...).emit()`.

### Batches

In a batched request (`httpBatchStreamLink`), the spine carries `trpc.batched: true`, `trpc.batch_size`, and `trpc.procedures` (every invocation counted, including repeats of the same procedure). `status` is the **transport** status of the shared response (often `207`); when a procedure errors, `trpc.path` points at the failing procedure and `error.*` carries its error code.

## Sinks

`amplio add sink json|otlp|console` **edits `telemetry/logger.ts`** — it inserts the sink import and appends it to the `init()` sinks array (the CLI prints the inserted lines). If you install a sink through the shadcn CLI instead (`npx shadcn add @useamplio/sink-otlp`), the file is dropped but **not** wired — add the import and sinks-array entry yourself, or run `amplio add sink otlp` afterwards. `amplio doctor` warns when a sink file exists but is not referenced in `logger.ts`.

## Server-only

Do not import `telemetry/logger`, `init()`, or `getLogger()` from `"use client"` components — the runtime uses `node:async_hooks`. Share event schemas via `@useamplio/amplio/events` (`defineEvent` only). Client-originated events: POST to a `withAmplio`-wrapped route handler and emit server-side.

### Client-originated events, worked example

```ts
// telemetry/events/ui/feedback-submitted.ts (defineEvent only — client-safe)
import { defineEvent } from "@useamplio/amplio/events";
import { z } from "zod";

export const UiFeedbackSubmitted = defineEvent(
  "ui.feedback.submitted",
  z.object({ feedback: z.object({ rating: z.number().int().min(1).max(5) }) }),
);
```

```ts
// src/app/api/events/feedback/route.ts (server — emits the event)
import { getLogger } from "@useamplio/amplio";
import { NextResponse } from "next/server";
import { withAmplio } from "~telemetry/middleware/next";
import { UiFeedbackSubmitted } from "~telemetry/events/ui/feedback-submitted";

export const POST = withAmplio(async (request) => {
  const body = (await request.json()) as { rating: number };
  getLogger()
    .child(UiFeedbackSubmitted)
    .set({ feedback: { rating: body.rating } })
    .emit();
  return NextResponse.json({ ok: true });
});
```

```tsx
// any "use client" component — plain fetch, no amplio import needed
await fetch("/api/events/feedback", {
  method: "POST",
  body: JSON.stringify({ rating: 5 }),
});
```

Two rows result: the `http.request` spine for the POST and the `ui.feedback.submitted` domain row, correlated by `request_id`.
